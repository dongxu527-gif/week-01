二、每天 / 每周做什么

频率动作在哪做
每次巡检后当场新增一条记录，高风险当天处理巡检台账
每天下班前看一遍待处理和高风险未闭环后台 / 台账
每周五导出本周 CSV，发项目群或存档台账 → 导出 CSV
每两周导出知识库 JSON + 台账备份 JSON，本地留一份台账 / 知识库
每月检查学校列表、成员角色、DeepSeek 余额后台 / Vercel / DeepSeek

三、账号与权限

角色能做什么不能做什么
admin后台、学校管理、成员角色、全部工具不能代替学校做安全决策
inspector巡检台账、报价、方案、知识库不能进后台、不能改学校、不能改角色
成员离职：先去 Supabase → Authentication → Users 禁用账号，再在后台把角色改成 inspector 或删除 profile。

四、备份与恢复

数据备份方式恢复方式
巡检记录台账 → 备份 JSON / 导出 CSV台账 → 导入备份（JSON）
知识库文档知识库 → 导出全部（JSON）目前需要手动重新录入；后续加导入
学校 / 成员Supabase 表导出（开发人员操作）Supabase 表导入
免费版不要只依赖平台备份。重要数据至少每月在本地留一份，文件名带日期。

五、出问题先查哪里

现象先查处理
打开台账跳到登录页账号是否登录重新登录；忘记密码在 Supabase 重置
后台提示没有权限profiles 表里的 role让 admin 在后台改成 admin
方案生成显示“本地模板”Vercel 是否有 DEEPSEEK_API_KEY补环境变量后 Redeploy
知识库回答“资料里没有”文档是否录入、问法是否差太远补文档或换关键词再问
页面打不开Vercel 部署状态看 Deployments 日志，重新部署

六、成本大概多少

项目现在备注
Vercel免费额度静态页面 + 少量 Serverless 调用
Supabase免费额度数据库、登录、RLS
DeepSeek按量付费方案和问答，单次通常几分钱
域名可选不买也能用 vercel.app 链接

七、10 分钟演示顺序

  1. 首页 30 秒：公司是谁、服务哪三类学校、怎么联系。
  2. 报价 1 分钟：改人数和天数，生成报价，复制报价单。
  3. 方案 2 分钟：填入示例学校，生成方案，指出“需现场核实”的边界。
  4. 台账 2 分钟：新增一条高风险记录，改状态，导出 CSV。
  5. 知识库 2 分钟：问“公司有哪些资质”，展示来源引用。
  6. 后台 2 分钟：看统计、学校列表、高风险、成员角色。
  7. 收尾 30 秒：强调“人防 + 机器人 + 数据闭环”，先试点再推广。

八、接下来 30 天

周目标验收
第 1 周选 1 所学校试点，录真实资料台账有 20 条真实记录
第 2 周让 2 个同事用手机录入和提问不再需要你在旁边教
第 3 周用真实数据生成 1 份方案和 1 份报价客户能看懂，愿意继续谈
第 4 周复盘：删掉没人用的功能，补最常用的列出下一版 3 个优先级

九、安全红线

不要把学生姓名、家长电话、身份证号、人脸照片放进知识库或 AI 对话；
不要把 Supabase service_role key 写进任何前端文件；
不要把 DeepSeek key 发到群里；
AI 生成的方案、报价、回答，必须人工审核后再发给客户。
